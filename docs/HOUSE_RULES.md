# 有意偏离原版的地方

这里只记**明知道原版是什么样、仍然决定改**的条目，以及改法和怎么改回去。
「还没挖到所以先顶着」的临时实现不属于这里，那些记在 `GAME_LOGIC.md` 对应小节的
**[未确认]** 标记里。

| 条目 | 原版 | 我们改成 | 出处 |
|---|---|---|---|
| 呐喊 | 攻击力 **×1** | 全军攻击力 **×1.5** | §9.15 |
| 火矢 | 弓兵攻击力 **×1** | 弓兵攻击力 **×2** | §9.15 |

## 呐喊 / 火矢

原版 `b.V()` 里这两个增益乘的都是 1：

```
165: iload_3   166: iconst_1   167: imul      // cd&0xF0 == 64  呐喊
203: iload_3   204: iconst_1   205: imul      // cd&0xF0 == 80  火矢（且 bU==2）
```

这不是反编译丢了乘数——`javap -c b.class` 看字节码就是硬编码的 `iconst_1`。
说明文案写着「全军攻击力增加」「箭手攻击力大大增加」，但代码里没接。
六个计策点能力里**只有连弩是真的**（射程 `by2` 由 5 变 7，即 4 格 → 6 格）。

花 8 点和 10 点计策点买不到任何效果，显然不是设计意图，所以接上：

```csharp
// BattleRules.BuffMul()
case 4: return 1.5f;                          // 呐喊：全军
case 5: return arm == Arm.Gong ? 2f : 1f;     // 火矢：只加弓兵
```

**要回到原版行为**：把 `BattleRules.BuffMul()` 的返回值全改成 `1f`。
增益的编码、持续回合、消耗的计策点都照原版没动
（`cd` 高 4 位能力号、低 4 位剩余回合，每轮减 1）。

## 战棋层计策：两处原版没给数

16 种计策的落点合法性（`b.a(int,int,byte,boolean)`）、成功率与伤害（`b.a(short,short,byte,short)`）、
结算（`b.a(short,byte[],byte,byte,int,boolean)`）都是逐段移植的，见 `BattleRules.PlotLegal / PlotRoll / PlotMessage`。
顺带发现 **劫火（14）在原版永远用不出去**——合法性函数 2349 那两行两个分支都 `return false`。菜单里置灰。

两处原版没给数、我定的：

| 项 | 我定的 | 依据 / 怎么改 |
|---|---|---|
| 被困几日（虚兵 4 / 连环 7 / 奇门遁甲 17） | 三种都 **3 日**，奇门遁甲每日再减 100 兵 | 说明文案 `d.q[10]`「被困三天」、`d.q[15]`「日减100兵」；代码里没找到 `bv` 递减处。改 `BattleField.TRAP_DAYS` |
| 十面埋伏踩中扣多少兵 | **150** | 原版 3703 走 `E(); j(...)`，没读到数；按共杀那档。改 `BattleField.AMBUSH_LOSS` |

## 主公不豁免：也能劝降 / 笼络 / 俘虏

原版把「忠诚 > 99」当主公标记：单挑劝降 `b.k()` 第一行直接 `return false`，
情报和列表里忠诚画「--」。我们的设定是**主公到最后也能被劝降、笼络、俘虏**：

| 处 | 原版 | 我们 |
|---|---|---|
| 单挑劝降 `Persuade` | `P > 99 → false` | 去掉这一行，忠诚 100 照常进公式（要把体力打到个位数才可能） |
| 计策笼络 `PlotRoll(8)` | `P > 35 → false` | 不变（主公 100 本来就过不了 35 这关，靠单挑劝降那条路） |
| 情报 / 列表显示 | `--` | 显示 100 |
| 战后俘虏 | 战略层未接 | 接的时候主公不豁免 |

劝降公式里的 `n`：原版只特判 `4→6、5→8`，德智都 100 时 `x=101` 落进 6 那格没特判，
反而比 95 档低。我们把 `n ≥ 5` 一律抹成 8。回原版改回 `else if (n == 5) n = 8;`。

要回到原版：`Persuade` 加回 `if (foe.Loyal > 99) return false;`，显示处改回 `--`。

## 地形码 1 / 3：补了效果（原版无）

原版 1 和 3 只弹「是否进入村庄?」，「是」之后 `aq=5/6` 进空循环，没有任何效果
（`GAME_LOGIC.md` §8.2）。其他版本是武器店 / 金粮店。我们按战场里说得通的补了一版：

| 格 | 效果 | 文案 |
|---|---|---|
| 3 粮仓 | 我方粮 +100~300 | 「征得粮草: N」（原版搜索战报原话） |
| 1 武库 | 武将兵器升一档（`ArmLv+1`，上限 23） | 「获得兵器 X」（原版 `d.s[]` 有此句式） |

一座建筑一场仗只能用一次（`usedBuildings`），再进「村中已空」。4 号药庐照原版治疗。
回原版：`OnLanded` 里 1/3 分支删掉。

## 战棋层移动：方向键改成亮"可达范围"（消耗规则照原版）

原版 `c.java 5180-5262`：按「移动」后方向键按一下走一格，那格没人且 `b.h(格,兵种) ≤ 机动力` 才走，
按确定 `E()` 收尾（落在建筑格问进村）。没有"可达范围"，也没有每将一次的限制。
iPhone 没方向键，一格一格点太累，所以把"方向键能走到的所有格"一次算出来亮给玩家：
规则不变（每格 `b.h` 消耗、有人的格过不去、总消耗 ≤ 机动力），点哪格就按最省的路走过去扣机动力，落地即确定。
两处走样：原版有取消键（位置和机动力还原 `R`），触屏没做；原版不挪也弹村庄，我们只在挪过之后弹。

## 撤退 / 粮尽 / 回合到头之后，城归谁还没算

原版这四种收场（`c.java` 4473 `W = 7 / 9 / 20 / 21`）走同一条路：我方余将逐一「撤退武将 X」选退路，
撤完回战略层，由 `D()` / `L()` 结算城池归属、部队并入、金粮入库。
我们只把战场这一半接了：逐将撤退照原版，撤完弹一句原版的文案（粮尽「我军粮草耗竭,全军撤退!」、
到点「战争回合结束！」、失城「敌军占领了 X!」）。城归谁、兵和粮怎么处理是战略层的事，还没接。
唯一现在就改了库的是失城那条：把 `cityRuler[城]` 记给敌方主公，不然撤退菜单还会把这座城列成退路。

## 阵型战散不了场时的兜底

原版阵型战唯一的出口是武将的棋子离盘（体力被打光，或者下了撤退令走出边界），没有回合上限。
理论上双方都被墙隔开、谁也够不着谁时会一直转。我们加了一条：连着 20 拍谁都没做成事 → 「双方罢兵」，
`cc` 记 0，双方只结算兵力，谁也不死。原版没有这一条。

## 单挑宝物：30 / 40 / 69 号那一支不接（原版这条本身是坏的）

原版 `af()` 里还有一支 `else if (bP == 1) { R[ax] = 14; }`（龙牙刀）。
`bP` 追出来了：它是**战略层 AI 这一步要干什么**（1 调兵 / 2 内政 / 3 出征，`au`/`av` 是起止城，
`bl()` 拿 `bR[bP][bQ]` 走脚本）。可是单挑的「全力」`d(short,short,short)` 第二行又把它覆写成 3 ——
J2ME 省内存的变量复用（或者就是个 bug）。于是这条奖励到底给不给，取决于战略 AI 上一步碰巧是哪一类、
以及这场单挑有没有人出过「全力」，等于抛硬币。不接。
曹操(61)→青釭剑、4 号→龙鳞宝铠、管辂(1)→倚天剑、24 号→七星剑，这四条是照原版接的。

## 战后善后 L() / K()：接了城和库，没接势力表

原版打完一座城要办四件事：城主与太守易主、原势力城数 −1（归零则势力灭亡 `bG = 4`）、
守军逐个退往邻城（第一个还把城库的金粮带走）、活着的部队进城当驻军。
我们的数据里没有势力槽和城数组，所以**势力灭亡判定没接**；其余三件都按原版办了：
城主改成得城方主公、太守记成他家第一员、驻军数写回 `cityCount`、
金粮按原版那条判（守将还活着且有城可退 → 库被带走；守将倒了或无城可退 → 归攻方）。

## 机动力：开局一律从 0 起算（原版攻方那条忘了清零）

每回合的机动力是「`b(兵)` 发的基数 + 上回合没用完的」，封顶 `c(兵)`；
第一天 `R()` 的 `if (bA > 1)` 不刷新，用的就是开场那一次，所以第一天只有基数
（四将各 1000 兵 = 4000 → 第 4 档 → 28，上限 42）。**这是原版的数，不要"修"。**

唯一的出入：开场那次原版写成 `bk = a(..., bk)`，守方那条（b.java 6080）之前有 `bk = 0`，
攻方那条（1988）**没有**——理论上会把上一仗剩下的机动力带进新的一仗。
我们两边都按清零处理，和守方一致。玩家看过之后决定保持现状，不复刻这个毛病。

## 主公孤家寡人时忠诚掉到 60

原版主公忠诚恒 100，而围捕 `Y()` 卡 `P > 99`、单挑劝降 `k()` 也卡 `P > 99`，
等于主公永远擒不住、劝不动。玩家定的家规是：**一方打到只剩主公一人时，他的忠诚自动降到 60**。

这样原版那两道 `P > 99` 的门可以原样留着（不用改判定），家规自己把它打开；
而且降到 60 之后仍要吃围捕公式里「忠诚 ≥ 80 减 10」以下那几档的对待，
体力也还得先磨到 40 以下，抓起来并不轻松。实现见 `BattleField.UpdateLoneRuler`，
每个 Tick 查一次，触发时提示「XX 众叛亲离,军心动摇!」。

## 开局等级压到 1–3：给所有人成长空间

**原版**：228 名武将的起始等级分成五档——

| 原版等级 | 人数 | 代表 |
|---|---|---|
| 1 | 42 | 无名小将 |
| 2 | 86 | 文聘、廖化、曹仁 |
| 3 | 70 | 刘备、马良、关平 |
| 4 | 11 | 曹操、孙坚、司马师 |
| 8 | 19 | 关羽、张飞、吕布、赵云、许褚、典韦 |

没有 5、6、7 级，等级是跳着给的。问题出在两头：**19 个猛将开局就顶格**
（经验 30000 封顶，`b.f(short)` 只升不降，再打也不涨），而新登场的武将从 1 级
起步，中间隔着 30000 点经验——按"打掉对方多少兵就得多少经验"的口径，
这是三万个兵的差距，一局仗打不出几百。新人永远追不上，老将一点不动。

**我们**：按原档位压缩，相对高低不变，成长空间还给所有人。

| 原版等级 | 家规等级 | 起始经验 | 人数 |
|---|---|---|---|
| 1 / 2 / 3 | 1 | 0 | 198 |
| 4 | 2 | 2000 | 11 |
| 8 | 3 | 4000 | 19 |

经验落到新等级的档位起点，从头往上爬。关羽开局 3 级，练到 8 级要 26000 点；
一个无名小将练到 3 级只要 4000 点——追得上了。

**为什么不直接改 `officers.csv`**：那张表是从原版 ROM 里抽出来的，
要保持和原版逐字节一致，好随时回去对账。映射放在 `BattleRules.LoadOfficers`
读档的那一刻做（`StartLevelHouseRule`），改口径只动一行表。

**连带影响**（敌我同等，是对称的）：

- 阵型战的兵种配比按新等级走，开局骑兵比原版少。
- 能用的计策种数按新等级走：`PlotCount` 里 12 种以上要求等级 4 以上，
  所以开局谁都开不满，得先练。
- 计策成功率与伤害吃等级差，双方都压缩了，差距比原版小。

## 太守府：原版 `e(short,int)` 会除零，我们补了个夹子

`b.java:10555` 算巡查涨多少人口：

```
n2 = 智力 * 金子 / 100
lo = n2 / 2;  hi = n2 - 1
结果 = (lo + s() % (hi - lo + 1)) * 100
```

`n2` 为 0 时 `hi = -1`、`lo = 0`，区间长度是 0，`s() % 0` 直接抛 ArithmeticException。
城里金子不足 10（`aV()` 会把花费压到城里现有的金子）而武将智力又够 17 的时候真能撞上。
我们把空区间当 0 处理，别的一律照抄。

另外记两条**不是 bug、是原版数据就长这样**的事，免得下次又去翻：

- **治水开局用不出来**。36 座城的防灾 `q[]` 全是 99，已经顶格，
  `X()` 每次都弹「此城无惧水旱」。它是一条**修补**指令，不是成长指令——
  只有水旱灾害（`b.java:6436` 把 `q` 打下去）之后才轮得到它。
- **开垦 / 劝商 / 巡查 的统治 +1 开局也是白给**。36 座城的统治 `k[]` 同样全是 99，
  原版那句 `if (k[by] < 99) k[by]++` 一直不成立。统治要靠民变（`6498` 一次掉 0~14）
  掉下来之后才涨得回去。

## 功曹府（人事）：和原版不一样的几处

规则全在 `Personnel.cs`，逐条标了原版行号。有意偏离的：

- **搜索的金粮那档也会除零**。`f(short,byte)` 里 `德*17/10 − 德*12/10` 在德 0~1 时为 0，
  `s() % 0` 会抛异常。同样把空区间当 0。
- **登用去掉了 `j()` 里那次结果被丢掉的 `nextInt()`**（GAME_LOGIC §7 已记）。
- **奖赏的赏额**：原版屏 12 是四位数字逐位键入；触屏改成 −10/−1/+1/+10，默认给到上限
  `min(城中金子, 100)`，最小 1（原版填 0 会弹「奖赏黄金不能为0!」，这里根本填不出 0）。
- **结果屏带说话人头像**：原版这类话都走 `a(武将, 文字)`，本来就带脸；
  前置条件被挡时说话的是太守（`a(j[au], …)`）。
- **年度登场只接了 `l(年)` 那一段**。`aE()` 后半段 26 条写死的「子承父业」事件
  （`aa/ab/ac` 三张表，b.java:1427）里的武将号和 3.2.2 的武将表对不上：
  程普被写成北斗之子、马铁马休写成司马懿之子，而且多数人开局就已仕官，
  照搬会把同一个人塞进两座城。等哪天找到对得上的那版武将表再接。
- **只能在自家城里下令**。原版城池轮换只走 `d[势力][]`；我们的地图能点进任何城，
  所以在 `Game.OnCommand` 里补了归属判断，别人的城只能看。

两条**原版数据就长这样**的事：

- **开局全图只有 2 个未发现的在野**（164 个 189 年登场的人里 162 个开局就仕官）。
  搜索「偶遇贤才」要等 190 年起每年一批新人进搜索池（190:20 / 191:10 / 192:9 / 193:12 人）。
- **任命在君主亲领的城里用不了**（「此城乃君主治所!」），洛阳就是。而且这条**不扣令**
  （步骤表 `bR[9]={3,97,0}`，结尾走 `aK()` 不走 `aL()`）。

## 校场（军事）与战争：修掉的原版 bug 和改动

规则在 `Military.cs`（移动 / 征兵 / 输送）与 `War.cs`（战争的出征与善后），逐条标了原版行号。

**修掉的原版 bug**（整体逻辑照原版，只把会卡死、会算错的地方补上）：

- `K()` 3337：胜仗后收编「被敌方擒去的我将」那段循环 `n` 不自增，敌方无路可退时死循环再越界、游戏卡死。
  我们照意图写：逐个收编，满 10 人进在野。
- `C()` 2877：丢城时从我方城列表里删城写成了自赋值，城没删掉、最后一座反而丢了。我们按城主直接改归属。
- `bE`（我方主将阵亡标记）从不复位：此后每场败仗都会把携带金粮再送敌城一遍，金粮翻倍。我们只算当场。
- `z()` 1981：进攻开战不清机动力，第 1 日带着上一场的余数。我们每场新开 BattleField。
- 原版敌方「全军逃窜」「粮尽逃窜」（W=5 / W=6 → `L()`）我们之前只弹了一句话没给城，现已按原版算攻占。
- 满 30 日与敌粮同日耗尽：原版 W=20 会盖掉 W=6（应胜反败）。我们先结算粮草，敌粮尽算我方胜。

**有意的改动**：

- 选目标城：照原版切到大地图屏 4 去点（移动 / 输送 / 战争 / 离间 / 招揽 / 情报 / 自建建都全一样）。
  能选的城套呼吸的金环，点一下选中、再点一次确定；点了不能选的城提示「请选择高亮的城池」；「作罢」回城内。
- 屏 14 的金粮、屏 8 / 9 的数目：原版四位数逐位键入；我们改成加减钮（−100 −10 +10 +100 满）。
- 空城直接占领时原版携带金粮不封顶 9999，这里统一封顶。
- 同盟还没做，战争目标暂不排除盟友城。
- 敌方继位：原版先查写死的继承名单 `f[][]`，那张表还没挖出来，先走它的兜底规则（智 + 武 + 德 最高）。

## 集市：四座建筑对应原版四个店

常平仓 = 粮店（`x[]&8`）、武库 = 武器店（`&1`）、郡学 = 学院（`&2`）、药庐 = 医院（`&4`），逐城核过 36 城全对。
规则在 `Market.cs`，逐条标了原版行号。

- 原版武器店**没有买马**，新版浮窗里那条「购买马匹」是空想出来的，已删。
- 武器店的货架档 `y[]`（cities.csv 第 21 列，-1 = 无武器店）决定每架卖哪四样；
  四件名品（关王刀 / 蛇矛 / 狼牙枪 / 圣者之衣）卖出一件，那座城的货架档改成 1，名品就此下架。
- 学院的学费按修习前的智力定（<30 → 30 金、<60 → 20 金、其余 10 金），智力 ≥ 80 的不收。


## 战场村庄：改回原版（2026-09-25）

之前以为原版地形 1 / 3 没效果、自己补了「兵器升一档 / 征粮 100~300、每格一场一次」的家规——**看漏了**。
