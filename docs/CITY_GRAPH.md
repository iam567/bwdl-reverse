# 城池连通图

大地图不是自由移动,而是一张**固定的无向图**。
甲、乙、丙三城若甲-乙-丙串联,甲**不能**直接到丙。

## 数据来源

硬编码在 `b.java` 的构造函数里,不在任何数据文件中:

```java
byte[][] byArrayArray = new byte[37][];   // 下标 1..36，0 不用
byArrayArray[1]  = new byte[]{3, 5};       // 西平 → 武威、天水
byArrayArray[9]  = new byte[]{5, 6, 10, 14};
...
this.D = byArrayArray;                     // D[城][k] = 第 k 个邻接城
byte[] byArray2 = new byte[37];
byArray2[1] = 2;                           // E[城] = 邻接数量
...
this.E = byArray2;
```

导出数据:`extract/data/city-adjacency.json`、`extract/data/city-edges.csv`

## 三个指令共用这张图

| 指令 | 目标判定 | 源码 |
|---|---|---|
| 移动 | `i[目标] == i[当前]` 同势力 | `Q(byte)` b.java:8800 |
| 输送 | `i[目标] == i[当前]` 同势力 | `R(byte)` b.java:8816 |
| 战争 | 异势力 **且** 非同盟(查 `X[]`/`W`) | b.java:9075 |

`i[城]` = 该城君主的武将 ID,等值即同一势力。

## 城池坐标(大地图)

坐标同样硬编码在 `c.java` 构造函数里,是一张 **`bE[32][30]` 的网格**,
每格存城市 ID,0 表示空。

```java
byte[] byArray20 = new byte[30];
byArray20[5]  = 4;      // bE[23][5] = 4  → 成都
byArray20[21] = 27;     // bE[23][21] = 27 → 庐江
byArrayArray[23] = byArray20;
```

**索引是 `bE[y][x]`**,由绘制代码确认:

```java
while (n < 32) { while (n2 < 29) {
    if (bE[n][n2] > 0) this.a(graphics, 势力色, n2 * 6, n * 6);
    //                                          ↑x        ↑y
```

- **每格 6 像素**,光标绘制在 `(bv*6+3, bw*6+3)`
- 实际占用 **28 列 × 30 行 = 168 × 180 像素**,放进 176×220 的屏幕
- 36 座城全部落位,无重叠

导出:`extract/data/city-coords.json`(含格坐标与像素坐标)
渲染脚本:`extract/drawmap.js`

### 坐标验证

| | |
|---|---|
| 邻接城对 平均格距 | **4.2** |
| 全部城对 平均格距 | 13.3 |

邻接的城在几何上明显更近,说明坐标与邻接表是同一套设计,没有错位。

布局符合真实地理:武威/西平在西北,云南/建宁在西南,
襄平在辽东最东北,会稽/荑州在东南,洛阳长安居中。

### 跨度最大的几条边(最"不合地理"的)

| 边 | 格距 |
|---|---|
| 成都 ↔ 江陵 | 9.5 |
| 汉中 ↔ 襄阳 | 6.7 |
| 云南 ↔ 成都 | 6.3 |
| 零陵 ↔ 江陵 | 6.3 |
| 成都 ↔ 江州 | 5.7 |

成都↔江陵那条实际跨越了整个三峡,是纯粹的玩法设计。
重画地图时这几条线会显得最突兀,但**建议保留** ——
它们是蜀汉能出川的关键通道,删掉会让成都变成死地。
