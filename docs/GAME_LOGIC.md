### `x[]` 是位掩码,不是四个独立列 **[已验证]**

### 势力槽位是 9 个,不是 7 个 **[已验证]**

君主表只有 7 行,但势力索引的数组全部开成 9 长:

```java
public byte[]   a = new byte[9];
public short[]  b = new short[9];
public byte[]   c = new byte[9];
public byte[][] d = new byte[9][];
```

`b.aH()` 开头单独初始化 **索引 8**:

```java
this.a[8] = 0; this.b[8] = 0; this.c[8] = 0;
this.d[8] = new byte[37];          // 37 = 36 城 + 1
```

索引 0 空置,1–7 是七方诸侯,**8 号槽位留给自建武将自立的势力**,
与上面 229–231 三个武将槽位配套。复刻时势力相关的容器要按 9 开,
地图上的势力配色也要连第 8 方一起准备。

### 2.2 三种攻击 —— 是**单挑**里的三招，不是部队互砍 **[已验证]**

`b(short,short,short)` / `c(...)` / `d(...)` 的调用点全在 `c.d/e/f(Graphics,boolean)`
（c.java:2273 / 2323 / 2391），扣的是 `L[]` **体力**，不是 `J[]` 兵力：

```java
byte by = this.b.c(this.X, this.b.cz, this.b.cy);
this.b.L[s] = (byte)(this.b.L[s] - by);       // 扣体力
```

配合 §2.5 的决策函数看：返回 0/1 = 这两招，2 = 拼命(必杀)，4 = 撤。

```java
// [已验证]
byte 普通攻击(a,b,c) {                     // b(short,short,short)
    byte d = 基础伤害(a,b,c) / 20;
    return d > 0 ? d : 1;                  // 必中，最低 1
}

byte 强攻(a,b,c) {                         // c(short,short,short)
    byte 命中 = (a == 攻方) ? 7 + cC : 7 - cC;
```

### 2.3 战力计算与兵种克制

```java
// [已验证] b.ae()
void 战前结算() {
    攻方战力1 = 武力[攻] + 武力[攻] * af[R[攻]] / 100;
    攻方战力2 = 武力[攻] + 武力[攻] * af[S[攻]] / 100;
    守方战力1 = 武力[守] + 武力[守] * af[R[守]] / 100;
    守方战力2 = 武力[守] + 武力[守] * af[S[守]] / 100;
    计算克制();
    ...
}

// [已验证] b.ad()
void 计算克制() {
    int d = R[攻] / 8 - R[守] / 8;     // 0/1/2 三大类
    cC = (d == 0) ? 0 : (d == 1 || d == -1) ? -1 : +1;
}
```

**加成表 `af[]`(完整还原):**

| 兵种大类 | 等级 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 组 0(R 0–7) | 5% | 7% | 12% | 18% | 25% | 50% | 50% | 50% |
| 组 1(R 8–15) | 6% | 10% | 15% | 20% | 24% | 26% | 45% | 50% |
| 组 2(R 16–23) | 8% | 10% | 12% | 20% | 25% | 30% | 50% | 50% |
| 副属性(S 24–31) | 5% | 8% | 10% | 15% | 20% | 25% | 50% | 60% |

**克制是循环的(石头剪刀布):** 差为 0 → 平;差为 ±1 → 劣势;差为 ±2 → 优势。
`cC` 同时作用于攻守双方(`7 + cC` vs `7 - cC`),
所以强攻命中率的实际摆动是 **60% ↔ 80%**,必杀是 **10% ↔ 30%**。
这就是原版"兵种压制感"的全部来源。

### 2.8 寻路

```java
// [已验证] b.a(byte,byte,byte,byte,byte[],byte[][],byte[],byte)
```
贪心逐格逼近,不是 A*:

1. 先按 `(dx, dy)` 的象限和 `|dx| vs |dy|` 关系,挑一个**相邻可站格**作为落脚点
   (`f(bm[y][x]) == 0` 判定可通行)
2. 从起点向落脚点走,每步优先消解较大的轴向差,
   被占据格(`bm[y][x] & 0xC0 != 0`)则改走另一轴
3. 方向编码 **1=上 2=下 3=左 4=右**,最多 **16 步**
4. 最后把路径数组**整体反转**

复刻可以直接换成 A*,但**移动步数上限 16 必须保留**,否则战场节奏会变。

```java
// [已验证] b.f(short 武将, byte 上限)
int 搜索(int 武将, int 上限) {
    int roll = s() % 120;
    if (roll > 智力[武将]) return 0;                    // 智力 ≥120 → 永不空手

    int 数量, 类型;
    if (roll > 79) {                                    // 高段位:稀有事件
        int r = s() % 100;
        数量 = r < 5 ? 4 : r < 15 ? 3 : r < 40 ? 2 : 1;
        类型 = 4;

        类型 = 3;
```

### 5.3 `q[]` = 治水 **[已验证]**

城内管理画面把 `q[]` 画在标着「治」的格子里(见 §0 的标签对照表),
所以 `q[]` 是**治水**。下面这段矛盾是当时不知道语义时的记录,保留是因为
**衰减方向的疑问并没有因此消失**,复刻时仍要按实际代码走一遍。

**已验证的机械行为:**
- CSV 初值 **99**,上限被 `if (q > 99) q = 99` 钳住
- 每回合自然衰减 `q -= q/10 + 1`
- 被某个内政指令提升:`q += n2/2 + 1`
- 存档序列化在每城记录的 **offset 17**

**仍待解释:** 衰减量与 `q` 成**正比**(`q * 值/2 / 阈值`),
即治水越高、每回合掉得越多;而初值就是上限 99,内政的「治水」指令再往上加。
若 `q` 是治水程度,这更像是「维护成本随水利规模上升」,
但该式究竟服务于哪条结算仍未定位——取决于 `D()`/`E()` 是否真被调用。

**尚未找到 `D()` / `E()` 的直接调用点** —— 它们可能是死代码,
或通过某个分派表间接调用。**复刻前必须先确认这一点**,
否则整个内政-灾害循环会做错。

## 7. 复刻注意事项

1. **整数除法必须保留。** 所有公式都是 Java 整数运算(向零取整),
   换成 float 会系统性偏移。C# 里用 `int` 并确认除法语义一致。
2. **RNG 调用顺序必须一致** 才能复现原版手感;
   但 §3.1 那次被丢弃的 `nextInt()` 是 bug,建议去掉并记录差异。
3. **`ap.nextInt() % N` 可能为负** —— §2.4 单挑和 §3.2 劝降都用了它。
   照抄会让概率偏离直觉值,这是原版行为的一部分。
4. **移动上限 16 步、数据缓冲 12000 字节** 这两个硬上限影响手感/容量,别随手改。

### 9.11 阵型战是实时自动战，不是回合制 **[已验证]**

下完令之后**兵棋自动走位、贴上就打**，画面实时刷新：

```java

    while (true) {
        if (ao.a != 0) { ao.h(); ao.a = 0; }  // 收按键
        if (aq > 0) return;                   // 分出胜负就退出

```

> 早先我按「第 N 日推进」来理解，找了半天「每轮减员函数」找不到——
> 因为压根没有「轮」。是玩家拿模拟器截图回来才发现方向错了。

#### 一秒动一枚，轮到谁才读令

主循环（b.java:5480）里真正推进的是这两句：

```java
this.cL = (byte)(this.cL + 1);
if (this.cL < 10) continue;      // 攒够 10 帧 ≈ 1 秒才动一次
...
this.cH = this.s(this.cD);       // 只动 cD 这一枚，然后 cD++
```

而 `b.s(by)` 的第一行是：

```java
this.bY[0][by] = this.cj[this.bU[0][by]];   // 轮到这枚棋，才去读它那一兵种当前的令
```

**这两条合起来就是原版能微操的地方**：兵棋一枚一枚地动，`cD` 从 1 往后推，
一方走完换另一方；每枚棋轮到自己时才去查 `cj[兵种]`。
所以四个骑兵里第一个已经往前走了，你这时把骑兵切成「撤退」，
**剩下三个就会掉头**——不需要、也没有「开打 / 暂停」这种按钮。

`cj[兵种]` 就是 §9.9 那四道令。敌方的行为由 `b.h(n)` 按
「是不是攻城 / 我方是攻还是守」分派。

#### 攻击力与防御力（`b.d(boolean,byte)` b.java:1196）

**都挂在武将的武力 `M[]` 上**：

| | 攻击力 `bV` | 防御力 `bW` |
|---|---|---|
| 武将本人 | `武力 + 武力 × af[R] / 100` | `武力 + 武力 × af[S] / 100` |
| 骑兵 | `武力` | 同上 |
| 弓兵 / 步兵 | `武力 × 3 / 5` | 同上 |

注意攻击用的是**兵种等级 `R`** 的加成，防御用的是**副属性 `S`** 的加成，两张表不同（§2.3）。
攻击力最低钳到 1。

#### 打一次掉多少兵（`b.V()` b.java:5211）

