```java
// [已验证] b.a(short 武将, short 分子, short 分母)
int 基础伤害(int 武将, int 分子, int 分母) {
    int n = 武力[武将] * 分子 / 分母;
    if (n > 武力[武将] * 2) n = 武力[武将] * 2;   // 上限
    if (n < 武力[武将] / 3) n = 武力[武将] / 3;   // 下限
    return n + n / 10;                            // 固定 +10%
}
```

### 2.3 战力计算与兵种克制

```java
// [已验证] b.ae()
void 战前结算() {
    攻方战力1 = 武力[攻] + 武力[攻] * af[R[攻]] / 100;
    攻方战力2 = 武力[攻] + 武力[攻] * af[S[攻]] / 100;
    守方战力1 = 武力[守] + 武力[守] * af[R[守]] / 100;
    守方战力2 = 武力[守] + 武力[守] * af[S[守]] / 100;
    计算克制();
    ...
}

// [已验证] b.ad()
void 计算克制() {
    int d = R[攻] / 8 - R[守] / 8;     // 0/1/2 三大类
    cC = (d == 0) ? 0 : (d == 1 || d == -1) ? -1 : +1;
}
```

**加成表 `af[]`(完整还原):**

| 兵种大类 | 等级 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 组 0(R 0–7) | 5% | 7% | 12% | 18% | 25% | 50% | 50% | 50% |
| 组 1(R 8–15) | 6% | 10% | 15% | 20% | 24% | 26% | 45% | 50% |
| 组 2(R 16–23) | 8% | 10% | 12% | 20% | 25% | 30% | 50% | 50% |
| 副属性(S 24–31) | 5% | 8% | 10% | 15% | 20% | 25% | 50% | 60% |

**克制是循环的(石头剪刀布):** 差为 0 → 平;差为 ±1 → 劣势;差为 ±2 → 优势。
`cC` 同时作用于攻守双方(`7 + cC` vs `7 - cC`),
所以强攻命中率的实际摆动是 **60% ↔ 80%**,必杀是 **10% ↔ 30%**。
这就是原版"兵种压制感"的全部来源。

### 2.8 寻路

```java
// [已验证] b.a(byte,byte,byte,byte,byte[],byte[][],byte[],byte)
```
贪心逐格逼近,不是 A*:

1. 先按 `(dx, dy)` 的象限和 `|dx| vs |dy|` 关系,挑一个**相邻可站格**作为落脚点
   (`f(bm[y][x]) == 0` 判定可通行)
2. 从起点向落脚点走,每步优先消解较大的轴向差,
   被占据格(`bm[y][x] & 0xC0 != 0`)则改走另一轴
3. 方向编码 **1=上 2=下 3=左 4=右**,最多 **16 步**
4. 最后把路径数组**整体反转**

复刻可以直接换成 A*,但**移动步数上限 16 必须保留**,否则战场节奏会变。

## 4. 搜索 / 巡查事件

```java
// [已验证] b.f(short 武将, byte 上限)
int 搜索(int 武将, int 上限) {
    int roll = s() % 120;
    if (roll > 智力[武将]) return 0;                    // 智力 ≥120 → 永不空手

    int 数量, 类型;
    if (roll > 79) {                                    // 高段位:稀有事件
        int r = s() % 100;
        数量 = r < 5 ? 4 : r < 15 ? 3 : r < 40 ? 2 : 1;
        类型 = 4;
    } else if (roll > 59 && 上限 != 0) {
        数量 = s() % 上限;
        类型 = 3;
    } else {
        int lo = 德[武将] * 12 / 10;                    // 德 × 1.2
        int hi = 德[武将] * 17 / 10;                    // 德 × 1.7
        数量 = (lo + s() % (hi - lo)) * 6 / 10;         // 再 × 0.6
        类型 = (roll % 2 == 1) ? 2 : 1;
    }
    return 类型 | (数量 << 8);                          // 打包
}
```

**智力决定能否触发,德决定收获多少。** 对应的界面文案:
`一无所获!` / `征得粮草:` / `获得黄金` / `偶遇贤才` / `寻得宝物.`

### 5.3 ⚠ `q[]` 的语义待确认

**已验证的机械行为:**
- CSV 初值 **99**,上限被 `if (q > 99) q = 99` 钳住
- 每回合自然衰减 `q -= q/10 + 1`
- 被某个内政指令提升:`q += n2/2 + 1`
- 存档序列化在每城记录的 **offset 17**

**矛盾点:** 衰减量与 `q` 成**正比**(`q * 值/2 / 阈值`),
即 `q` 越高损失越大;但 `q` 初值是 99(最高),且由内政指令**提升**。
这两点无法同时用"治安"或"灾害强度"解释。

**尚未找到 `D()` / `E()` 的直接调用点** —— 它们可能是死代码,
或通过某个分派表间接调用。**复刻前必须先确认这一点**,
否则整个内政-灾害循环会做错。

## 7. 复刻注意事项

1. **整数除法必须保留。** 所有公式都是 Java 整数运算(向零取整),
   换成 float 会系统性偏移。C# 里用 `int` 并确认除法语义一致。
2. **RNG 调用顺序必须一致** 才能复现原版手感;
   但 §3.1 那次被丢弃的 `nextInt()` 是 bug,建议去掉并记录差异。
3. **`ap.nextInt() % N` 可能为负** —— §2.4 单挑和 §3.2 劝降都用了它。
   照抄会让概率偏离直觉值,这是原版行为的一部分。
4. **移动上限 16 步、数据缓冲 12000 字节** 这两个硬上限影响手感/容量,别随手改。
